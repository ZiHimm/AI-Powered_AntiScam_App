## Issues

### 1. HANG UP: fixed in `c158247` ✅
- `f2dc0f7`: failed every time WhatsApp's buttons were hidden (02:46:32, 03:20:33, 03:32:21): `Couldn't find the end-call
  button`, with no "after showing the call controls" line.
- `c158247`: worked on both tries (03:57:05, 03:59:27), each time on **try 2**, from a single user tap. No
  `Call screen buttons: …` line was needed. The first reveal-tap never found the button on this phone, so the second
  tap is what makes it work.

### 2. Frame error when the face touches the screenshot edge ❌
```
03:07:21.737  Frame error: y + height must be <= bitmap.height()      (chin off the bottom)
03:26:02.834  Frame error: x + width must be <= bitmap.width()        (×7 between 03:26:02 and 03:26:13)
03:35:01.444  Frame error: x + width must be <= bitmap.width()        (×2)
```
The face box isn't clamped to the bitmap before cropping. After the 03:07 error, **no face lines for 13 s**
(03:07:21 → 03:07:34). Later errors didn't stall (frames continued in between). If a stall happens before a match, the call is never checked.

### 3. A photo of Son on a screen only just passes the new rule
The photo matched Son at **0.86–0.88 with a gap of only 0.05**, exactly at the "≥ 0.05 closer" limit (one frame:
`maybe Son 0.84, not sure (next: daughter 0.85)`). Before Son was re-enrolled, two photo calls never matched Son at all.
For the demo story ("scammer shows Son's face"), this is fragile: it depends on the photo, lighting and enrolment. Live Son
was 0.43–0.91 with gaps 0.09–0.34. Options (your call): enrol Son from the same photo/video used on stage, or have a
separate rule for the demo.

### 4. One decision per call (design question)
At 03:31 and 03:40 the call started with the holder's own face (enrolled Daughter), so **Daughter** was asked. Switching
to Son's photo afterwards changed nothing; the call stays locked on the first decision. A real scammer could start with
an innocent face and then switch to a deepfake of Son. Consider **starting a new check when a different family member's
face appears** after the first decision.

### 5. Smaller things
- **Early "not family" message:** `Caller is not one of your family faces.` appears after 1–2 "not in family" frames, e.g.
  03:31:51, **one second before** the same call matched Daughter (03:31:52). On stage it flashes a contradicting message.
- **A single confident wrong frame is possible:** 03:25:51 `Face ≈ daughter (0.82) (next: son 0.95)` passed the new
  rule; the next two frames were Son, so 2-of-3 saved it.
- **The stranger came close to "mom"** (1.00–1.01, the "This is me" face); never near the 0.92 ping limit.
- **Daughter's phone kept dropping off the relay** (02:47, 02:57, 03:10, 03:30, 03:44) when Family Verify was in the background
  while that phone ran WhatsApp. The detector reported `(Daughter offline)` correctly. This one is for `mobile/` (Brian), not
  the detector.
